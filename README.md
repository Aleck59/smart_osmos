# Smart Osmos H2

<img src="brands/logo.png" alt="Smart Osmos" height="96">

Прошивка ESPHome для контроля бытового обратного осмоса на плате **ESP32-H2 Super Mini**
и интеграция для Home Assistant.

Устройство считает объём воды двумя расходомерами, измеряет TDS, ведёт ресурс пяти
ступеней очистки, показывает всё на маленьком OLED и управляется **одной кнопкой**.
Wi-Fi у ESP32-H2 нет, поэтому связь и обновление прошивки идут по Bluetooth LE.

* Совместимо с мобильным приложением из проекта [VGCH/smart_osmos](https://github.com/VGCH/smart_osmos) —
  UUID сервиса и формат JSON сохранены один в один.
* Home Assistant подключается по BLE через интеграцию из этого же репозитория (HACS).
* Обновление прошивки — по BLE, через внешний компонент [`esp32_ble_ota`](https://github.com/slynn1324/esp32_ble_ota).

## Состав репозитория

```
esphome/
  osmos-h2.yaml                 ← основной файл прошивки (все пины — в начале)
  components/smart_osmos/       ← внешний компонент: расчёты, хранение, BLE-протокол
custom_components/smart_osmos/  ← интеграция Home Assistant (устанавливается через HACS)
web/index.html                  ← прошивка по Bluetooth прямо из браузера
brands/                         ← иконка и логотип интеграции
tools/make_icon.py              ← генератор иконки
docs/WIRING.md                  ← подключение и питание
docs/PROTOCOL.md                ← описание BLE-протокола
.github/workflows/              ← сборка прошивки и проверка интеграции
```

## Оборудование

| Компонент | Модель |
|-----------|--------|
| Плата | ESP32-H2 Super Mini |
| Расходомеры | 2 × YF-S402B |
| Качество воды | TDS Meter v1.0 (аналоговый) |
| Дисплей | OLED 0.91", SSD1306, 128×32, I²C |
| Управление | одна тактовая кнопка |

Распиновка, требования по питанию и варианты подключения кнопки — в
[docs/WIRING.md](docs/WIRING.md).

## Быстрый старт

```bash
pip install esphome
esphome compile esphome/osmos-h2.yaml     # проверить и собрать
esphome upload esphome/osmos-h2.yaml      # первая прошивка — по USB
```

Дальше прошивать можно по воздуху — см. следующий раздел.

Собранная прошивка появляется артефактом каждой сборки GitHub Actions
(`smart-osmos-firmware`) и прикрепляется к релизам.

### Настройка под себя

Всё, что обычно требуется поменять, собрано в блоке `substitutions` в самом
начале `esphome/osmos-h2.yaml`: номера пинов, тип подключения кнопки, импульсы
на литр, ресурс каждой ступени, имя BLE-устройства и пароль обновления.

## Обновление по Bluetooth

Провод нужен один раз — для самой первой прошивки. Дальше контроллер обновляется
по воздуху, с ноутбука, двумя способами.

### Из браузера

В репозитории лежит [`web/index.html`](web/index.html) — страница на Web Bluetooth:
выбираете файл, она проверяет образ, подключается к контроллеру и заливает прошивку
с прогрессом и журналом. Ставить ничего не нужно, но открыть её двойным щелчком
нельзя: Web Bluetooth работает только в защищённом контексте.

```bash
# в корне репозитория
python3 -m http.server 8000 --directory web
```

Затем откройте <http://localhost:8000> в **Chrome, Edge или Opera** на компьютере.
`localhost` считается защищённым контекстом, поэтому Bluetooth будет доступен.

Порядок: выбрать `firmware.ota.bin` → проверить, что страница показала верные имя
проекта и версию → «Подключиться и прошить» → выбрать `SMART OSMOS` в списке
браузера. Около мегабайта заливается примерно за минуту-полторы; по завершении
устройство перезагружается само.

Если репозиторий публичный, ту же страницу можно включить на GitHub Pages
(Settings → Pages, папка `/web`) и открывать по https-адресу без локального сервера.

> Safari и Firefox Web Bluetooth не поддерживают — там страница честно об этом
> скажет. На Linux может потребоваться включить
> `chrome://flags/#enable-web-bluetooth-new-permissions-backend`.

### Скриптом

Вариант без браузера, из репозитория компонента
[slynn1324/esp32_ble_ota](https://github.com/slynn1324/esp32_ble_ota):

```bash
pip install bleak
python3 esp32_ble_ota_upload.py --device "SMART OSMOS" \
        --password "OeN12345" firmware.ota.bin
```

В обоих случаях нужен именно `firmware.ota.bin` — не `firmware.bin` и не
`firmware.factory.bin`. И страница, и скрипт проверяют заголовок образа и
откажутся заливать не тот файл.

Имя устройства и пароль берутся из `substitutions` в `osmos-h2.yaml`
(`ble_name` и `ota_password`).

## Экраны

Дисплей 128×32 разбит на шесть страниц. По краям видны стрелки — они показывают,
что страница есть слева или справа.

| # | Экран | Что показывает |
|---|-------|----------------|
| 1 | Фильтры | Пять ступеней в ряд: номер и под ним шкала остатка ресурса |
| 2 | TDS | Слева крупно текущее значение и под ним среднее за сутки, справа график за 24 ч |
| 3 | Расход | Две колонки — водопровод и чистая: сверху расход (л/мин), снизу объём за минуту |
| 4 | Статистика TDS | Минимум / среднее / максимум за сутки и коэффициент прочистки |
| 5 | Объём и замены | Суммарные объёмы и дата замены ступени (ступени сменяются раз в 3 с) |
| 6 | Настройки | Список настроек (компонент `graphical_display_menu`), два пункта на экран |

Экран 128×32 вмещает ровно две строки, поэтому вся вёрстка на них и построена:
верхняя строка с `y = 0`, нижняя с `y = 15`, шрифт Roboto 14 (высота строки 17 px).
Ничего мельче на экране нет — включая пункты меню.

### Индикация ресурса

| Остаток | Поведение шкалы |
|---------|-----------------|
| больше 20 % | обычная заполненная шкала |
| меньше 20 % | номер и шкала мигают с частотой 0.25 Гц |
| меньше 5 % | мигают с частотой 0.5 Гц, шкала пустая и перечёркнута наклонной линией |
| 0 % | не мигает, шкала перечёркнута крест-накрест |

### Управление одной кнопкой

| Жест | На экранах 1–5 | В меню настроек |
|------|----------------|-----------------|
| Короткий клик | следующая страница | следующий пункт; при правке — увеличить значение |
| Двойной клик | предыдущая страница | отмена правки, выход из подменю, выход из меню |
| Удержание (0.6 с) | — (на экране 6 открывает меню) | войти в пункт / подтвердить значение |

Жесты разбираются вручную по нажатию и отпусканию кнопки. Штатный
`on_multi_click` для одной кнопки не подходит: не совпавшие шаблоны уходят
в `invalid_cooldown` на секунду и глотают следующий жест — из-за этого после
удержания переставал срабатывать двойной клик. Сейчас удержание срабатывает
ровно через `btn_hold_ms`, не дожидаясь отпускания, а второй клик выполняет
«назад» немедленно. Обе задержки меняются в `substitutions`.

Через **10 минут** без нажатий дисплей гаснет. Первое нажатие после этого только
будит экран и не выполняет действие. Таймаут настраивается в меню.

### Что есть в меню настроек

* **Калибровка** — калибровка расходомера чистой воды «на 1 литр», ручной ввод
  импульсов на литр для обоих расходомеров.
* **Ресурс, л** — ресурс каждой из пяти ступеней.
* **Замена фильтра** — отметить замену ступени (обнуляет счётчик и ставит дату).
* **TDS** — множитель и смещение калибровки, сброс суточной статистики.
* **Дисплей** — таймаут гашения и яркость.
* **Сервис** — наработка, суммарные объёмы, обнуление счётчиков.

### Калибровка расходомера «на 1 литр»

1. Меню → **Калибровка** → **Пуск (пролить 1 л)**.
2. Пропустить через линию чистой воды ровно один литр (мерной ёмкостью).
3. **Готово — 1 л налит**. Прошивка посчитает импульсы на литр и сохранит их.

То же самое доступно из Home Assistant кнопками «Калибровка: старт» и
«Калибровка: налит 1 литр».

## Home Assistant

### Установка через HACS

1. HACS → ⋮ → **Custom repositories**.
2. Добавить `https://github.com/Aleck59/smart_osmos`, категория **Integration**.
3. Установить **Smart Osmos** и перезапустить Home Assistant.
4. Контроллер найдётся сам через Bluetooth; если нет — «Добавить интеграцию» → Smart Osmos.

Нужен рабочий Bluetooth-адаптер (встроенный, USB или ESPHome Bluetooth Proxy
в зоне действия).

<details>
<summary>Если захочется подать репозиторий в каталог HACS</summary>

Для каталога HACS требует заполнить About у репозитория на GitHub — без этого
проверка `hacs/action` не проходит. Установке через «Custom repositories» это
не мешает, поэтому в CI обе проверки сейчас отключены
(`ignore: topics description` в `.github/workflows/hassfest.yml`).

Чтобы подать репозиторий в каталог, откройте его страницу на GitHub, нажмите
шестерёнку рядом с **About** и заполните:

**Description**

```
Контроллер бытового обратного осмоса на ESP32-H2: прошивка ESPHome и интеграция Home Assistant по Bluetooth LE
```

**Topics** (только строчные буквы, цифры и дефисы)

```
home-assistant  hacs  hacs-integration  esphome  esp32  esp32h2
bluetooth-low-energy  reverse-osmosis  water-quality  tds  custom-component
```

После этого уберите `topics description` из строки `ignore` в workflow — проверки
снова начнут работать. Иконку нужно отправить отдельно, см.
[brands/README.md](brands/README.md).

</details>

### Что появится

* **Датчики**: TDS (текущий, минимум/среднее/максимум за сутки), расход по обеим
  линиям, объём за минуту, суммарные объёмы, коэффициент прочистки, эффективность,
  а по каждой ступени — остаток ресурса, пропущенный объём и дата замены.
* **Двоичные датчики**: связь, идёт калибровка, ресурс на исходе, требуется замена.
* **Настройки**: ресурс каждой ступени, импульсы на литр, калибровка TDS —
  выключены по умолчанию, включайте те, что нужны в автоматизациях.
* **Кнопки**: отметить замену ступени, обнулить счётчики, сбросить суточную
  статистику, управление калибровкой.

Интеграция раз в час отправляет устройству время Home Assistant — именно оттуда
контроллер узнаёт дату, которую показывает на экране замен.

### Все настройки одной карточкой

Настройки → Устройства и службы → **Smart Osmos** → **Настроить**: откроется одна
форма со всеми девятью параметрами контроллера — импульсы на литр по обеим линиям,
калибровка TDS и ресурс каждой из пяти ступеней.

Значения в форму читаются прямо из устройства, а обратно уходит только то, что
вы изменили. Home Assistant их у себя не хранит, так что рассинхрона с
контроллером не бывает.

Те же параметры доступны и как сущности `number` — на случай автоматизаций, — но
по умолчанию выключены, чтобы не засорять карточку устройства. Включить нужные
можно в списке сущностей устройства.

### Своя карточка на панели

Проще всего собрать карточку с самой страницы устройства: **Добавить в панель** —
Home Assistant создаст карточку со всеми включёнными сущностями. Сущности ступеней
названы с номером в начале («1. Механическая очистка: …»), поэтому в любом списке
они выстраиваются по порядку ступеней.

### Иконка интеграции

Иконка и логотип лежат в [`brands/`](brands/). Home Assistant берёт изображения не
из репозитория интеграции, а из общего каталога
[home-assistant/brands](https://github.com/home-assistant/brands) — как отправить
их туда, написано в [brands/README.md](brands/README.md).

## Как считаются величины

**Объём.** Импульсы расходомера делятся на калибровочный коэффициент
(имп/л). Для YF-S402B `F = 98 · Q(л/мин)`, то есть 5880 импульсов на литр —
это значение по умолчанию, точное получается калибровкой.

**TDS.** Формула DFRobot с термокомпенсацией, как в исходном проекте:

```
ec  = U / (1 + 0.02 · (T − 25))
TDS = (133.42·ec³ − 255.86·ec² + 857.39·ec) · 0.5 · множитель + смещение
```

**Ресурс ступени.** Остаток = `100 − пропущено·100/ресурс`. Ступени 1–4 считают
входной объём, ступень 5 — объём чистой воды (это настраивается).

**Коэффициент прочистки** — отношение объёма чистой воды к водопроводной, в процентах.
