# BLE-протокол

Устройство рекламируется под именем **`SMART OSMOS`** и поднимает один сервис
с тремя характеристиками. Обмен — JSON в UTF-8, поле `key` задаёт тип сообщения.

```
Сервис            4fafc201-1fb5-459e-8fcc-c5c9c331914b
├── beb5483e-…26a8  read / write / notify — канал мобильного приложения
├── beb5483e-…26a9  read / notify        — расширенная телеметрия (Home Assistant)
└── beb5483e-…26aa  read / notify        — расширенная конфигурация
```

UUID сервиса и первой характеристики совпадают с исходной прошивкой проекта
[VGCH/smart_osmos](https://github.com/VGCH/smart_osmos), поэтому штатное мобильное
приложение работает без каких-либо доработок.

> **MTU.** JSON телеметрии занимает около 420 байт, что заметно больше базового
> BLE MTU в 23 байта. Прошивка сама поднимает локальный MTU до 512 (параметр
> `local_mtu`), клиенту достаточно запросить увеличение при подключении — Android
> и Home Assistant делают это по умолчанию.

## Команды приложения (запись в …26a8)

| Команда | Поля | Действие |
|---------|------|----------|
| `get_config` | — | В ответ придёт `config_data` |
| `get_data` | `en`: `"On"` / `"Off"` | Включить/выключить рассылку `real_time` раз в 500 мс |
| `c_config` | `c_in`, `c_off`, `prefiltr`, `membrana`, `postfiltr` | Импульсы на литр и ресурсы. `prefiltr` задаёт ресурс сразу ступеням 1–3 |
| `c_reset` | `r_totalIN_P`, `r_totalIN_M`, `r_totalIN_PO`, `r_totalIN_OUT` — каждое `"R"` | Сброс ресурса предфильтров / мембраны / постфильтра / суммарных счётчиков |
| `update` | `en`: `"On"`, `psw` | Разрешить обновление прошивки |
| `wifi`, `wifien`, `save` | — | Принимаются и игнорируются: у ESP32-H2 нет Wi-Fi |

### Расширения протокола

| Команда | Поля | Действие |
|---------|------|----------|
| `time` | `ts` (unix), `tz` (минуты) | Синхронизация часов. Отсюда берётся дата замены фильтров |
| `stage` | `n` (1…5), `limit`, `src` (0 — вход, 1 — чистая), `reset`: `"R"` | Работа с конкретной ступенью |
| `cal` | `act`: `start` / `finish` / `cancel`, `l` (литров, по умолчанию 1) | Калибровка расходомера чистой воды |
| `tds_cal` | `factor`, `offset`, `act`: `day_reset` | Калибровка TDS и сброс суточной статистики |

## Ответы

### `real_time` (…26a8, раз в 500 мс)

Полностью повторяет формат исходной прошивки. Числа передаются строками, как и в
оригинале. Поля `wi-fi_*`, `prs`, `mqttstat`, `ip` заполнены заглушками — на этой
плате нет ни Wi-Fi, ни датчика давления.

```json
{"key":"real_time","r_cur_in":"1234.50","r_cur_out":"310.20","wi-fi_s":"",
 "wi-fi_st":"disconnect","wi-fi_rssi":0,"tds":"38.40","prs":"0.00",
 "mqttstat":"disconnect","lp5mIn":"0.00","lp5mOut":"0.00","effic":"0.00",
 "timework":"1:04:20:11","res_P":42,"res_M":18,"res_PO":7,"ip":"0.0.0.0",
 "flow_in":"0.00","flow_out":"0.00","ota_en":false,"ota_link":"ble"}
```

`res_P` / `res_M` / `res_PO` — **израсходованный** процент ресурса (как в оригинале).
`res_P` берётся как максимум по ступеням 1–3.

### `config_data` (…26a8, по запросу `get_config`)

```json
{"key":"config_data","co_c_in":5880,"co_c_out":5880,"prefiltr":6000,
 "membrana":5000,"postfiltr":3000,"ssid":"","mqtt_serv":"","mqtt_user":"","mqtt_topic":""}
```

### `ext` (…26a9, раз в 2 с)

Всё, чего не хватает приложению: пять ступеней по отдельности, суточная
статистика TDS, минутный расход. `r` — **остаток** ресурса в процентах,
`u` — израсходованный объём в литрах, по одному элементу на ступень.

```json
{"key":"ext","tds":38.4,"tds_v":0.0912,"tds_min":31.0,"tds_avg":36.8,"tds_max":44.1,
 "f_in":0.00,"f_out":0.00,"m_in":0.000,"m_out":0.000,"t_in":1234.50,"t_out":310.20,
 "purif":25.1,"effic":0.0,"cal":0,"cal_p":0,"ts":1772280000,
 "r":[58.0,58.0,58.0,82.0,93.0],"u":[2520.0,2520.0,2520.0,900.0,210.0]}
```

### `ext_config` (…26aa, раз в 30 с)

```json
{"key":"ext_config","c_in":5880.0,"c_out":5880.0,"tds_factor":1.0000,
 "tds_offset":0.00,"tz":180,"dt":10,
 "limit":[6000,6000,6000,5000,3000],"date":[1772280000,0,0,0,0],"src":[0,0,0,0,1]}
```

## Обновление прошивки

Обновление идёт по отдельному сервису внешнего компонента
[`esp32_ble_ota`](https://github.com/slynn1324/esp32_ble_ota):

```
Сервис  424F5441-0001-1000-8000-00805F9B34FB
├── …0002  CONTROL  BEGIN / ABORT / COMMIT
├── …0003  DATA     поток блоков прошивки
└── …0004  STATUS   ACK / NACK / PROGRESS / DONE / ERROR
```

Загрузка выполняется скриптом из того же репозитория:

```bash
pip install bleak
python3 esp32_ble_ota_upload.py --device "SMART OSMOS" \
        --password "OeN12345" firmware.ota.bin
```

Использовать нужно именно `firmware.ota.bin` — не `firmware.bin`
и не `firmware.factory.bin`.
